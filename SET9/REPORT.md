## 1. Цель и постановка

Сравнить стандартные алгоритмы сортировки строк (QuickSort, MergeSort) со специализированными:

- тернарный **String QuickSort**;
- **String MergeSort** с LCP-сравнениями (конспект, неделя 30);
- **MSD Radix Sort**;
- **MSD Radix Sort + String QuickSort** при размере подмассива `< 74` (мощность алфавита).

Сортировка — прямой лексикографический порядок. Метрики: среднее время (мкс), среднее число **посимвольных** сравнений.

---

## 2. Тестовые данные (`StringGenerator`)

- Алфавит: 74 символа (`A–Z`, `a–z`, `0–9`, `!@#%:;^&*()-`).
- Длина строк: 10…200.
- Размеры массивов: 100…3000, шаг 100.
- Типы:
  - **Random** — случайный порядок;
  - **Reverse** — обратный лексикографический;
  - **NearlySorted** — отсортированный + ~5% случайных swap;
  - **Prefix** — общий префикс длины 50.
- Для каждого типа генерируется массив длины 3000, подмассивы берутся префиксом (`getSubarray`).
- Seed: **42**.

---

## 3. Методика измерений (`StringSortTester`)

- 5 независимых прогонов на конфигурацию, в отчёт — среднее.
- Время: `high_resolution_clock`, микросекунды.
- Сравнения: класс `SortMetrics`, счётчик увеличивается при каждом сравнении символов.
- **QuickSort (стандарт и строковый):** опорный элемент — **середина** подмассива (`pivotIndex`).
- **MSD+QS:** переключение на String QS при `размер < 74`.
- **MSD без QS:** распределение по байтам (256 корзин); посимвольных сравнений нет.

Полные данные: `sorting_results.csv` в репозитории.

## 4. Теоретические оценки

| Алгоритм | Время (типичная оценка) | Сравнения символов |
|----------|-------------------------|-------------------|
| QuickSort | O(n log n) сравнений строк | до O(n log n · L) |
| MergeSort | O(n log n) | до O(n log n · L) |
| String QuickSort | O(n log n) проходов по символам | на практике меньше |
| String MergeSort | **O(Σ LCP(R) + n log n)** | не больше O(Σ LCP + n log n) |
| MSD Radix | O(n · w), w — длина ключа | 0 (подсчёт) |
| MSD + QS | гибрид | сравнения только в QS-фазе |

L — средняя длина строки, Σ LCP(R) — сумма LCP в результате сортировки.

| Алгоритм | Время, мкс | Сравнения |

| QuickSort | 357.75 | 55 352 |
| StringQuickSort | 306.44 | 35 441 |
| MergeSort | 2380.71 | 44 472 |

**Вывод:** StringQuickSort быстрее стандартного QuickSort и делает меньше сравнений. MSD+QS — второй по скорости. StringMergeSort медленнее стандартного MergeSort из-за накладных расходов на LCP-структуры. MSD без QS проигрывает гибриду.

**Вывод:** На обратном порядке стандартный QuickSort быстрее, чем на случайном (меньше сравнений). StringQuickSort сохраняет преимущество по сравнениям. StringMergeSort снова медленнее MergeSort.

## 6. Сравнение стандартных и адаптированных алгоритмов

1. **String QuickSort vs QuickSort:** одинаковый выбор опорного (середина); выигрыш за счёт трёхпутевого разбиения по символу на глубине, без полного сравнения строк на каждом шаге. Особенно заметно на Prefix (экономия 90% сравнений).
2. **String MergeSort vs MergeSort:** теоретически оптимальнее (O(Σ LCP)), но на практике проигрывает по времени из-за накладных расходов на структуры `StringWithLCP` и дополнительные вызовы `lcpCompare`.
3. **MSD vs MSD+QS:** гибрид стабильно быстрее чистого MSD на всех типах данных; порог 74 соответствует условию.
4. **Префиксные массивы:** наибольший разрыв между стандартными и строковыми методами — подтверждает мотивацию задачи A1.

## 7. Реализация StringMerge (замечание)

Слияние поддерживает инвариант `ki = LCP(X, Si)`, `pj = LCP(X, Wj)` из конспекта. После выбора элемента из `P` или `Q` значения `ki`/`pj` для следующей итерации восстанавливаются через `LcpCompare` с последней строкой в `R`.

## 10. Заключение

Эксперимент подтверждает: специализированные строковые алгоритмы снижают число посимвольных сравнений на структурированных данных (общий префикс) и могут улучшать время. String QuickSort показал лучшие результаты среди всех алгоритмов сравнения. MSD+QS с порогом 74 — практичный компромисс. String MergeSort демонстрирует асимптотическую идею O(Σ LCP + n log n), но требует более лёгкой реализации для конкуренции по скорости.
